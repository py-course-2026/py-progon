# «Прогон» — автоматическая проверка учебных заданий

Сквозной проект курса «Python: второй уровень». Вы пишете его с нуля, тикет за тикетом: от ТЗ по письму заказчика до сервиса, который принимает решения студентов, запускает тесты в изоляции, хранит попытки и отдаёт ведомость.

## Легенда

Вы — разработчик в небольшой студии «Кодовый двор». Заказчик — Колледж связи и информатики: 300 студентов, три преподавателя, решения проверяют вручную. Колледж хочет свою систему проверки заданий — «как GitHub Classroom, только своё». Тимлид — Денис Юрченко, он пишет тикеты и принимает PR. Требования приходят письмами от заказчика — Ирины Павловны Сомовой.

## Правила проекта

1. **Сначала ТЗ, потом код.** Каждая функция системы следует из требования ТЗ, каждое требование — из письма заказчика.
2. **Только стандартная библиотека Python**, пока тикет не разрешит другое. Для тестов и проверки стиля — pytest и ruff.
3. **Каждый тикет — pull request** в `main` с зелёными проверками. В описании PR — что сделано, как проверено и на что обратить внимание ревьюеру.

## Что где

```text
progon/            ваш код: пакет progon
tests/             ваши тесты
docs/              ваши документы: ТЗ, руководство пользователя
letters/           письма заказчика
tickets/           тикеты — по одному на неделю
checks/            проверки тикетов: читайте, но не меняйте
```

## Рабочий цикл

```bash
uv sync               # один раз: Python 3.14, pytest, ruff и пакет progon в .venv
make check            # проверки всех тикетов
make check-tz1        # одна проверка
make update           # новые тикеты, письма и проверки из шаблона курса
uv run progon --help  # ваша программа
uv run pytest         # ваши тесты
```

Проверки гоняют все тикеты сразу. Новые тикеты появляются каждую неделю: выполните `make update` — он заберёт из шаблона курса новые `tickets/`, `letters/` и `checks/`, не трогая ваш код и документы, — и закоммитьте обновление отдельным коммитом.
