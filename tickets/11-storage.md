# PRG-11. История прогонов в базе

**Автор:** Денис Юрченко, тимлид · **Неделя:** 11

Коллеги, «Прогон» уже сам прогоняет решения, но результаты живут до конца команды: закрыли терминал — пропали. А Ирина Павловна с первого письма просила: хранить все попытки, потому что бывают споры «я же сдавал» [А5], и чтобы попытки нельзя было изменить задним числом (ФТ-06 нашего ТЗ). Файл JSON для этого не годится: его правят в блокноте. Нужна база.

## Что сделать — `progon/storage.py`

### 1. Схема и миграции

- SQLite, модуль `sqlite3`. Таблица прогонов (кто, какое задание, когда, статус, сколько тестов прошло из скольких, балл, время) и таблица результатов тестов, которая ссылается на прогон.
- Версия схемы — в `PRAGMA user_version`. При открытии база доводится до текущей версии: выполняются только недостающие изменения. Сегодня версия одна, но через месяц схема изменится, а базы колледжа терять нельзя.
- Внешние ключи включены (`PRAGMA foreign_keys = ON` — в SQLite по умолчанию выключены).

### 2. Попытки неизменяемы — на уровне базы

`UPDATE` и `DELETE` таблиц прогонов и результатов отклоняет **сама база**: триггер `BEFORE UPDATE … BEGIN SELECT RAISE(ABORT, '…'); END`. Код «Прогона» и так их не меняет — триггер защищает от всего остального: скрипта администратора, ручного запроса, будущей ошибки.

### 3. Класс `Storage(path)`

- Контекстный менеджер: `with Storage("progon.db") as db:` — соединение закрывается само.
- `save_run(login, task, submitted, result, score) -> int` — прогон и результаты всех его тестов **одной транзакцией**; возвращает номер прогона.
- `history(login)` — попытки студента по времени: `(задание, время ISO, статус, прошло, всего, балл)`.
- `attempts(task=None)` — попытки как объекты `Attempt` (PRG-5) по времени сдачи — для ведомости.
- `failed_tests(run_id)` — непрошедшие тесты прогона: `(тест, сообщение)`.
- Все данные — только параметрами `?`. Логин `o'brien` и задание `w1'; DROP TABLE runs; --` — просто данные.

### 4. Команды

- `progon run РЕШЕНИЯ ТЕСТЫ --db progon.db --task week01 [--max-score 10]` — прогон, как раньше, плюс запись каждого решения в базу. Балл — `max_score × прошло / всего`, два знака. `--db` без `--task` — ошибка входных данных.
- `progon history ЛОГИН --db progon.db`:

```text
Задание	Время	Статус	Прошло	Всего	Балл
week10	2026-11-16T10:12:03	ok	1	3	3
```

`tests/test_storage.py` — ваши тесты: сохранение и чтение, неизменяемость. Базу — в `tmp_path`.

## Критерии готовности

- `make check-db11` и `make check-cli11` зелёные, старые — тоже. Не забудьте `storage.py` в `docs/DESCRIPTION.md`.
- PR `prg-11` в `main`. В описании: почему попытки защищены триггерами, а не только кодом; что будет с базой, если между записью прогона и его результатов программа упадёт — у вас и без транзакции.
