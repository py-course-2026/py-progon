# PRG-10. Прогон решений

**Автор:** Денис Юрченко, тимлид · **Неделя:** 10

Коллеги, до сих пор «Прогон» получал готовый отчёт pytest — тесты запускал кто-то другой. Пора делать то, ради чего нас позвали: запускать тесты задания на решении студента самим [А2]. И с первого дня помнить про [А7]: решение студента может зависнуть, может запустить свои процессы, может что-то записать в папку. Сервер колледжа должен это пережить.

## Что сделать — `progon/runner.py`

### 1. `run_tests(solution, tests, timeout=10.0) -> RunResult`

- Скопировать папку решения во **временную** папку (`tempfile.TemporaryDirectory`), а в неё — папку тестов задания. Папка решения студента после прогона — без изменений: всё, что решение пишет, пишется в копию.
- Запустить `sys.executable -m pytest --junitxml=…` в копии как **отдельный процесс** (`subprocess.Popen`), так, чтобы тесты импортировали модули решения (`PYTHONPATH`). Никакого `shell=True`.
- **Таймаут**: если время вышло — убить не только pytest, но и **всё, что запустило решение**. Для этого процесс запускается в новой сессии (`start_new_session=True`) — у него своя группа процессов, — а по таймауту группа убивается целиком: `os.killpg(proc.pid, signal.SIGKILL)`.
- `RunResult` — неизменяемый: `status` (`"ok"` — pytest отработал и оставил отчёт; `"timeout"`; `"error"` — отчёта нет), `results` — кортеж `TestResult` из отчёта (PRG-4, PRG-5), `duration` в секундах, `output` — хвост вывода pytest для диагностики; свойства `passed` и `total`.
- Нет папки решения или тестов — `InputError`.

### 2. `run_many(solutions, tests, timeout=10.0, workers=4) -> list[RunResult]`

Несколько решений **параллельно**, не больше `workers` одновременно, результаты — в порядке решений. Подумайте, потоки или процессы: каждое решение и так идёт в своём процессе, а наша программа всё это время только ждёт.

### 3. `progon run РЕШЕНИЯ ТЕСТЫ [--workers N] [--timeout С]`

`РЕШЕНИЯ` — папка с подпапкой на каждого студента (имя подпапки — логин). Таблица через табуляцию, решения по алфавиту:

```text
Решение	Прошло	Всего	Статус	Время, с
anna	3	3	ok	0.4
ivan	1	3	ok	0.4
zoe	0	0	timeout	3.0
```

### 4. Тесты и документация

- `tests/test_runner.py` — ваши тесты: решение, которое проходит, и решение с бесконечным циклом. Учебные решения создавайте в `tmp_path`.
- Новый модуль — в `docs/DESCRIPTION.md`: проверка PRG-7 требует, чтобы там были все модули пакета, и напомнит.

Изоляции «по-взрослому» (память, сеть, файлы вне папки) здесь ещё нет — только время и отдельная папка. Об этом — в описании PR.

## Критерии готовности

- `make check-run10` и `make check-kill10` зелёные, старые — тоже. Проверка `kill10` работает в Linux и macOS: решение запускает свой процесс и зависает, и после таймаута этот процесс должен быть мёртв.
- PR `prg-10` в `main`. В описании: чем опасно `shell=True` для нашей задачи, почему `proc.kill()` мало, и какие требования [А7] и ФТ-12 из ТЗ ещё не выполнены.
