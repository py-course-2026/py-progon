# PRG-9. Статистика заданий и скорость на весь колледж

**Автор:** Денис Юрченко, тимлид · **Неделя:** 9

Коллеги, пилот закончился, со второй половины семестра — все двенадцать групп [Б8]. Это 300 студентов, 14 заданий и десятки попыток на каждое: файл курса вырастет с килобайтов до 25 МБ. На пилотных данных всё летало; как будет на настоящих — никто не знает. Узнаём заранее, измерениями, а не догадками. И Ирина Павловна попросила ещё одну вещь: по каким заданиям студенты больше всего опаздывают и где средний балл провален.

## Что сделать

### 1. `progon stats ФАЙЛ`

```text
Задание	Попыток	Студентов	Средний балл	После срока
week01	3	2	7.5	33%
week02	2	2	6.25	50%
week03	2	2	8	0%
```

По каждому заданию, в порядке заданий: сколько попыток; сколько студентов сдавали хотя бы раз; средний **лучший засчитанный** балл среди сдававших (два знака, без лишних нулей; 0, если никто не сдавал); доля попыток после срока с учётом продлений — целые проценты. Столбцы через табуляцию.

### 2. Скорость на данных колледжа

`uv run python checks/perf9/bigcourse.py big.json` создаёт файл курса размером с колледж: 210 000 попыток. На нём `progon gradebook`, `progon stats` и `progon check` должны укладываться в 10 секунд каждая — это с запасом для медленных машин GitHub Actions; хорошее решение работает меньше секунды.

Порядок работы:

1. **Измерить**: `time uv run progon gradebook big.json`. Не гадать — мерить.
2. **Найти**: `uv run python -m cProfile -s tottime -m progon gradebook big.json | head -25`. Смотрите на `tottime` (время внутри функции) и `ncalls` (сколько раз вызвана): функция, вызванная миллионы раз, — подозреваемый номер один.
3. **Исправить** самое дорогое — обычно это алгоритм, а не мелочи: проход по всем попыткам внутри цикла, `in` по списку, повторный разбор одного и того же.
4. **Измерить снова** и убедиться, что проверки остались зелёными.

### 3. Отчёт — `docs/PERFORMANCE.md`

Разделы:

- `## Замеры` — время команд до и после, в секундах, на чём мерили;
- `## Профиль` — вывод cProfile до и после, в блоках кода, со строкой заголовка;
- `## Что ускорили` — пунктами: что было медленно, почему (какая сложность) и что сделали.

Если ваш код оказался быстрым с самого начала — честно так и напишите, а в «До» покажите профиль и замер наивного варианта (например, лучший балл через `Course.best` для каждой клетки ведомости): замерить на части данных и оценить на весь колледж.
