# PRG-3. Команда ведомости, исключения и журнал

**Автор:** Денис Юрченко, тимлид · **Неделя:** 3

Коллеги, ведомость считается — пора дать её людям. Пока без сервера и браузера: преподаватель выгружает данные курса в JSON и получает ведомость командой `progon gradebook`. Заодно наводим порядок, без которого дальше будет больно: свои исключения, понятные сообщения вместо трассировок и журнал.

## Что сделать

### 1. Исключения — `progon/errors.py`

- `ProgonError(Exception)` — базовое: всё, что «Прогон» выбрасывает сознательно, с сообщением для человека.
- `InputError(ProgonError)` — входные данные не читаются или не в том формате.
- `UnknownTaskError(ProgonError, ValueError)` — попытка по заданию, которого нет. Её теперь выбрасывает `best_scores` вместо `ValueError`; раз она ещё и `ValueError`, старые тесты PRG-2 не заметят разницы.

### 2. Данные курса — `progon/course.py`

`load_course(path)` читает файл курса и возвращает то, что нужно `gradebook`: сроки заданий, студентов, попытки, продления. Формат:

```json
{
  "tasks": {"week01": "2026-09-07T23:59", "week02": "2026-09-14T23:59"},
  "students": [{"login": "anna", "name": "Петрова Анна", "group": "ИИ-201"}],
  "attempts": [{"login": "anna", "task": "week01", "score": 10, "submitted": "2026-09-06T18:00"}],
  "extensions": [{"login": "anna", "task": "week02", "until": "2026-09-21T23:59"}]
}
```

Порядок заданий в ведомости — порядок ключей в `"tasks"`. Продлений может не быть. Даты — ISO 8601, `datetime.fromisoformat`.

Всё, что может пойти не так с файлом, превращается в `InputError` с сообщением, по которому преподаватель сам поймёт, что исправить:

- нет файла — имя файла;
- файл не JSON — имя файла и **номер строки** (он есть в `json.JSONDecodeError`);
- файл не в UTF-8 — имя файла и слово UTF-8;
- нет обязательного поля — имя поля;
- дата не в формате ISO — сама неправильная дата.

Исходное исключение не теряйте: `raise InputError(...) from e`.

### 3. Команда — `progon gradebook ФАЙЛ`

Печатает ведомость в stdout, столбцы через табуляцию: заголовок `ФИО  Группа  <задания…>  Итог`, затем строка на студента. Числа — без лишнего `.0`: `10`, `4.5`. Табуляция нужна не для красоты: такой вывод вставляется в Excel как таблица.

- `progon` без команды — справка, код 0; `--version` работает как раньше.
- Ошибка `ProgonError` — одна строка в stderr: `progon: ошибка: <сообщение>`, код завершения 1, **без трассировки**. Любое другое исключение — ошибка в нашем коде: его не ловим, трассировка нужна нам.
- `-v` — в журнал (stderr) идут сообщения уровня INFO: например, сколько прочитано студентов и попыток; `-vv` — DEBUG. Без `-v` stderr при успехе пустой.
- Журнал настраивает **только** `main()`. Модули пакета берут `logging.getLogger(__name__)` и ничего не настраивают: импорт `progon.gradebook` в чужую программу не должен менять её журнал.

Подкоманд станет много. Советую регистрировать их декоратором — как `@app.get` в FastAPI: `@command("gradebook")` над функцией кладёт её в словарь команд.

### 4. Тесты — `tests/test_cli.py`

Добавьте тесты команды `gradebook`: нормальный вывод и хотя бы одна ошибка входных данных.

## Критерии готовности

- `make check-cmd3` и `make check-err3` зелёные, старые проверки — тоже.
- PR `prg-3` в `main`. В описании — пример сообщения об ошибке для каждого из пяти случаев выше и объяснение, почему `UnknownTaskError` наследует сразу от двух классов.
